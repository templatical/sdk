Add language versions and translation to the template model. A template keeps every language in one shared block tree: `settings.locales` lists the versions, and each block's and the settings' `l10n[locale]` layer holds translated `text` (`LocalizedText`, `{ value, sourceHash }`), property overrides in `set` and `hidden`. `resolveLocale(content, locale, options?: { missing?: "throw" | "default" })` projects one version, also for layouts and their wrapper children (`missing: "default"` falls back to the document's default), and `localeCoverage` and `sourceHash` report missing and out-of-date text.

- Operations `addLocale`, `removeLocale`, `setDefaultLocale`, `updateBlockLocale` and `updateSettingsLocale`, with guarded inverses from `invertOperations` and a `locale` on block and operation locks. `setDefaultLocale` promotes a version to the default; `defaultLocaleGaps` lists the fields with a nonempty default that keep the old default's value and `localeHiddenBlocks` the blocks that refuse the change. `updateBlockLocale` refuses `hidden: true` on a layout's slot or a block containing it, and `moveBlock` and `addBlock` refuse placing the slot under a block a language hides.
- Translation contract `TranslationProvider`, `TranslationRequest`, `TranslationResult`, `TranslationErrorCode` and `LocaleString`, and the pure helpers `maskTags`, `unmaskTags`, `localeStrings` and `applyLocaleStrings`. They mask merge tags, logic tags and an optional `doNotTranslate` term list as placeholders, check them exactly on return and stamp extraction-time `sourceHash` values. A term may also appear in a translation as plain text beyond its placeholders.
- `Comment.locale` and `CommentInput.locale` carry the language a comment was written in.
- `elementIdIssues(content)` lists menu item, social icon, table row and table cell ids that contain `.` or `/`. `validateTemplate` reports them, and `addBlock`, `updateBlock` and `setContent` refuse one they add with `invalid_operation`; an id already on its block stays editable.
- A localized custom block's projection drops its default-language `renderedHtml`, so rendering it needs `renderCustomBlock`.
- `isSafeUrlAttribute(name, value): boolean` applies the editor sanitizer’s shared `isSafeHtmlUrl` policy to `HTML_URL_ATTRIBUTES`: `href`, `xlink:href`, `background`, `poster` and `src`. It takes character references decoded and normalizes browser URL controls; URLs without a scheme, fragments and `SAFE_LINK_SCHEMES` are accepted, with image data matching `DATA_IMAGE_SRC_PATTERN` accepted only in `src`: `data:image/` of type `png`, `jpeg`, `jpg`, `gif`, `webp` or `svg+xml` followed by `;`. `HTML_FORBIDDEN_ATTRIBUTES` (`srcdoc`, `ping`, `formaction` and `action`) are always refused, including empty or HTTPS values. Other attributes return `true`; callers still check tags and `on*` handlers. The editor’s DOMPurify sanitizer and `template-tools strings import` share these sets and the URL-value policy.

Stored-template compatibility: existing templates need no migration. The one exception is an element id containing `.` or `/`, which now fails validation; rename it. Keep every `@templatical/*` package on the same version.

TypeScript producers must set the required `AiRequestBase.locale` and `AiRewriteRequest.locale` fields to the active language, or `null` in the default view. `CollaborationRemoteChange.locale` is also required: producers must set it to the first locale operation’s language in a batch, excluding `setDefaultLocale`, or `null` when there is none. Code that builds these objects must set these fields even without localization enabled.
