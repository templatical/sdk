Add `strings export <template.json> --locale <tag>` and `strings import <template.json> <strings.json>` to exchange a language's strings as a `strings/1` JSON file. Export selects the gaps by default (`--only gaps|all`, `--block <id>`). Import re-masks the current defaults, applies every string whose `sourceHash` still matches and whose placeholders come back exactly, writes the accepted strings, and reports `{ applied, rejected }` with the reasons `stale`, `tags_changed`, `unknown_field`, `not_translatable` and `unsafe_html`; it exits `1` when any string was rejected. Export puts a stale entry's stored translation in `previous` and leaves its `text` absent; import never reads `previous`, so an untouched stale entry stays stale. Both commands refuse the template's default language with exit `1`, and import refuses a file whose `sourceLocale` isn't the template's default language with exit `2`, writing nothing.

`unsafe_html` follows the editor's rich-text URL policy for `href`, `src`, `xlink:href`, `formaction`, `action`, `ping`, `background` and `poster`, after the normalization a browser applies, so `javascript:`, `vbscript:`, `data:` (except images in `src`) and `file:` URLs are refused. It also refuses a comment, CDATA section or declaration the field's default doesn't contain, and a string that ends inside a tag. `text`-format strings, custom-block `text` and `textarea` fields included, are refused when they carry a tag, comment, CDATA section or declaration their default doesn't contain.

`--definitions <file>` loads custom-block definitions for `validate`, `render` and `strings`, so custom `text` and `textarea` translations validate from the CLI and render with each type's Liquid template and stylesheet; an invalid file exits `2`. `--do-not-translate <file>` protects a term list during `strings`, and `import --default-locale <tag>` sets the default language for a source that declares none; a value that isn't a language tag exits `2`.
